1

Escape leaves the row menu on screen

Keyboard and focusSeen in the running appSpec C8

What happens

Open a row’s ••• menu and press Escape. The app marks the menu as closed, but it stays visible and clickable.

What should happen

Escape hides the menu and returns focus to the ••• button.

2

One Escape closes two layers

Keyboard and focusSeen in the running appSpec C20

What happens

With a dialog open on top of the preview pane, a single Escape closes both.

What should happen

Escape closes only the top layer. A second press closes the pane.

3

Dialogs do not hold keyboard focus

Keyboard and focusSeen in the running appSpec C15

What happens

When a dialog opens, focus stays on the page behind it. The first Tab press lands on “Overview” in the sidebar, underneath the dimmed backdrop.

What should happen

Focus moves into the dialog when it opens and Tab cycles only through the dialog’s controls.

4

Row menus cannot be used with the arrow keys

Keyboard and focusSeen in the running appSpec C10

What happens

With a row menu open, Arrow Down does not move to the first item. In this run the first press closed the menu and focus stayed on the ••• button. The button and menu also carry no menu roles for screen readers.

What should happen

Arrow Down and Arrow Up move between items, Home and End jump to the ends, and the button announces that it opens a menu.

My earlier report said the arrow keys were “ignored”. This run shows they close the menu, which is the same gap seen more precisely.

5

Dark mode: opportunity names on Artists are invisible

Dark mode and colourSeen in the running appSpec P10, P2

What happens

Row titles are drawn in near-black on a near-black row. Measured contrast is 1.03 : 1. The artist tab bar stays white, and so does the focus queue on Overview.

What should happen

Titles use the light text colour on dark rows (at least 4.5 : 1). Tab bar and focus queue use dark surfaces.

8

Table columns run into each other

Layout and small screensSeen in the running appSpec T1, T19

What happens

On Artists the fee text runs into the deadline even at 1280px wide. At 1024px category, fee, deadline and stage all collide, and with the preview pane open the table is unreadable.

What should happen

Columns never overlap. Text is shortened with an ellipsis or the column is hidden.

What happens

At 768px the sidebar shrinks to icons, but the list of artist names keeps its full width and is drawn over the first column.

What should happen

The artist list is hidden, or shown as a fly-out, when the sidebar is collapsed.

10

13

The preview pane shows text that is not in the record

Wrong or invented informationSeen in the running appSpec H2

What happens

Every opportunity is labelled CONFIRMED. A missing theme is filled with a stock sentence. Every matched artist is described as “Oil painting, Installation, Mixed media” and CONFIRMED. The heading still uses the retired word “assigned”.

15

Clicking the Harsha tab shows Harsha’s pitches but the address stays #/artists. Refreshing, pressing Back or sharing the link returns to All Artists. The sidebar links do update the address.

16

Artists page forgets where you were

Lost state and feedbackSeen in the running appSpec S2, S4

What happens

Collapse a stage, scroll down, open a pitch and come back: the stage is open again and the scroll position has moved (260px before, 135px after). Open Calls does restore its position.

What should happen

Scroll position and open or closed stages are restored on return, as on Open Calls.

17

Error messages disappear after about three seconds

Lost state and feedbackSeen in the running appSpec C22

What happens

An error is shown in the same short-lived toast as a success message. It vanishes after 3.2 seconds and has no close button, so a slow reader never sees why the action failed.

What should happen

Error messages stay until dismissed and have a close button.

Test set-up: the server reply was replaced with a refusal so an error would appear. The wording of the message in the picture is mine; the toast and its timing are the app’s.

18

Add Artist loses typed data on a stray click

Lost state and feedbackSeen in the running appSpec C17, M16

What happens

Clicking outside the dialog closes it immediately, discarding what was typed. The four field labels are also not connected to their inputs, so a screen reader does not announce them.

What should happen

Ask before discarding typed data. Connect each label to its field.

19

“Save Draft” is offered on an opportunity already in the Inbox

WordingSeen in the running appSpec M5

What happens

Editing an Inbox opportunity shows Cancel, Save Draft and Save Changes. Save Draft belongs to capture only.

What should happen

Inbox opportunities show Cancel and Save changes. Moving to drafts stays in the ••• menu.

20

Many click targets cannot be reached by keyboard

Keyboard and focusSeen in the running appSpec A1, T4, C26

What happens

The outlined elements respond to a mouse click but are not buttons or links, so Tab skips them: every opportunity cell, every stage header, the profile menu, and the cards and rows on Overview.

What should happen

Each is a real button or link, reachable with Tab and activated with Enter or Space.

21

Retired wording is still on screen

WordingSeen in the running appSpec §12.3

What happens

The Artists page is titled “Artist Pipelines”. Each stage has two names (“Stage 1: Pitched · Pending Artist Review”). The tab reads “Archived”, not “Archive”. The preview pane says “ASSIGNED ARTIST ROSTER” (picture in issue 13).

What should happen

The agreed terms only: Artists; Pitched, Preparing, Submitted, Won, Closed; Archive; Matched artists.

22

When the deadline date has passed, the DEADLINE column shows “Closed”. “Closed” is also the name of the last pitch stage, so the row looks like a stopped pitch.

24

Bulk Set owner says it worked when it did not

Wrong or invented informationSeen in the running app (first run today)Spec C23

What happens

After choosing an owner for several opportunities, the app shows a success message without checking what the server replied. Here both changes were refused and the table still says “No owner”.

25

On Artists, bulk Archive removes the whole opportunity

Wrong or invented informationSeen in the running app (first run today)Spec T16

What happens

Ticking one artist’s pitch and pressing Archive archives the opportunity itself. Spring Prize was matched to Savya and Harsha; ticking only Savya’s pitch removed both pitches and moved the opportunity to the Archive as “Rejected at review”. Bulk Set owner has the same reach.

What should happen

On Artists the action applies to the ticked pitch only (close that pitch), or the button is not offered there.

26

“Copied!” appears when copying failed

Wrong or invented informationSeen in the running app (first run today)Spec C23

What happens

If the browser refuses to copy the email text, the app still shows “Copied!” and closes the window, so the user pastes whatever was on the clipboard before.

What should happen

Say that copying failed and leave the text on screen to select by hand.

Test set-up: the browser’s copy function was made to fail.

30

Some buttons can be pressed twice while saving

Lost state and feedbackRead in the code onlySpec C4

What happens

Several controls that call the server do not disable themselves while the request is running, so a double click can send the request twice.

What should happen

Every server-calling control is disabled and shows progress until the reply arrives.

No picture: the effect depends on timing and leaves nothing to see on a fast local server.
