1. Summary

  • The app already uses the Framer palette. Lime #d2e21a, forest #151e11 and cream #f4f5f1 match. The visible gap is not colour. It is how they are applied: the app mixes a cool navy #111827 with the forest ink, uses weight 700–800 where Framer uses 600, makes buttons 34–40px where Framer uses 48px, gives badges 8px corners where Framer uses pills and 16px, and uses heavy shadows where Framer is nearly flat.
  • The stylesheet carries at least eight competing :root token layers (teal, terracotta, coral/vanilla, forest, --tk-*, two dark sets) plus 3,273 !important. The Framer language cannot be applied reliably until there is one token set. This is the main dependency.
  • Framer has no dark theme. The dark theme must be derived from its forest surface and sage/lime accents, not copied. Framer's muted sage #b1b6a4 is a better secondary text colour on forest than the app's #9ea396.
  • One Framer habit should not be copied: a lime focus ring. Lime on cream is about 1.2:1 and fails non-text contrast. Use forest for focus on light surfaces.
  • Four decisions need an owner (section 5). Nothing has been implemented.

4.12 Light and dark rules

  1. Components may only use semantic tokens. No literal hex, no #fff, no inline colour.
  2. Dark theme is derived from forest, not inverted: surfaces step #0e100d → #161913 → #20221c.
  3. Lime keeps its value in both themes; text on lime is always #151e11.
  4. Status colours use the paired tokens in 4.1; every pair is checked ≥4.5:1 for text.
  5. Borders ≥3:1 only where they identify a control (inputs, selected states); decorative dividers may be lower.
  6. Illustrations and images get a 10% dim in dark theme.
  7. Both themes are verified route-by-route with a contrast sweep before release.

4.13 Illustration and imagery (optional)

Do not reuse Framer assets (they belong to the template). If used, commission an original, minimal lime/forest glyph set for empty states and the intake screen only. No photography.

5. Decisions needed

D1. Primary button colour. Framer: lime. App spec: forest. Recommendation: lime for the one page-level action (e.g. Add Open Call), forest solid for confirm actions inside forms and sheets. Alternative: keep forest everywhere and use lime for active states only (lowest change).

D2. Heading weight. Move 800 to 600 (Framer) or keep 700 for readability in dense screens? Recommendation: 600 for titles, 700 for table headers only.

D3. Sage band. Introduce #b1b6a4 as a quiet surface, or leave the app on cream/white/forest only? Recommendation: introduce sparingly (half-pane header, selected group).

D4. Active nav style. Lime pill (Framer accent) vs current white pill with side rule. Recommendation: lime pill.

6. Suggested sequence and dependencies

  1. Single token layer (4.1). Blocks everything else; also fixes the dark-theme leakage in the earlier audit.
  2. Radius, spacing and shadow scales (4.3–4.5). Depends on 1.
  3. Button, input, badge primitives (4.6, 4.7, 4.10). Depends on 1–2; introduce focus ring and 44px targets here.
  4. Dialog primitive (4.11) with the accessibility fixes. Depends on 1–3.
  5. Navigation and page header (4.9). Depends on the breakpoint fix (earlier audit F-04) and 3.
  6. Card and table surfaces (4.8, 4.10), then typography pass (4.2).
  7. Optional imagery (4.13).

Dependencies on the earlier audit: F-01 (dark colours), F-04 (breakpoints), F-06 (dialogs), F-07 (nav names), F-17 (dark input tokens). No cosmetic step should precede F-02 (hard-coded content) and the P0/P1 items in that report. Artist Pipeline changes remain out of scope.

7. Limits of this audit

  • Framer: only /features was inspected, at 1440, 1024 and 390. Tablet 810, other pages and the mobile menu open state were not captured (a click on the hamburger did not visibly open a menu in the capture).
  • Hover, focus and transition behaviour on Framer could not be verified; the pane's simulated hover did not register. Only the declared transition: all was observed.
  • The Framer page hides content until scrolled; sections were revealed by scrolling and then captured. Screenshots were taken at the pane's width and may crop the right edge.
  • Application: the local test server was down this session, so no new live measurements. Application figures come from CSS source and the earlier session. Computed values under 4.1 marked "verify" are proposals, not measured results.
  • Contrast figures for proposed pairs are estimates and must be computed before adoption.
  • The brief was truncated; the per-item fields are an assumption (see top).
  • Template licensing: the Framer page is a template; assets and copy must not be reused.
