A. Executive summary

Overall: the light-theme desktop experience is visually coherent and the core Open Calls workflow (list, search, preview, edit, assign) works. Beyond that the product is not release-ready. Four problems matter most:

  1. Dark theme is broken on most screens (F-01, Critical). Titles, labels, buttons and whole analytics cards keep light-theme colours. Contrast is as low as 1.0:1 (Entry, New, Settings titles) and 1.1:1 (Analytics, Artist Call buttons). Automated computed-style check: 26 failing text nodes on Entry and New, 21 on Analytics, 17 on Artists, 18 on Open Calls.
  2. Three headline screens show literal prototype content (F-02, Critical). The Artists table rows, the Analytics figures and the Dashboard greeting/date are string literals in app.js. Artists rows (e.g. "Autumn Production Grant 2027") do not exist in the data, and every one of them links to an Artist Call that answers "Call not found."
  3. Layout rules are not the approved ones (F-04, High). A stray max-width:840px rule breaks the 768–840px compact rail (icons float mid-screen). At exactly 1024px both the tablet-style and desktop rules match.
  4. Keyboard and assistive-tech access has gaps (F-05 to F-08, High). The profile/theme/sign-out trigger is a non-focusable div. The tablet icon rail has no accessible names. Team & People has no dialog role, initial focus or focus trap. Open Call rows open the preview by mouse only.

Counts: 2 Critical, 8 High, 14 Medium, 8 Low, 3 Enhancement (35 numbered findings; 32 verified or partly verified, 3 suspected: F-15, F-25, F-32). Escape handling, backdrop-click and focus restoration for the profile, assign, Team & People and half-pane overlays were verified working. No horizontal page overflow was found at any width swept. Table headers are 13.5px everywhere they appear.

High F-04 · Breakpoints differ from the approved layout rules (verified)

Route / component
App shell (all routes), Dashboard metric cards
Viewport
768–840px; 1024px
Actual
(a) @media (max-width:840px){#app{display:flex!important;flex-direction:column!important…}} (styles.css ~4364) applies inside the tablet range. At 768 and 800 the compact rail's icons sit vertically offset from the logo, headings centre, and a horizontal scrollbar appears on Open Calls. (b) @media (max-width:1024px) rules (lines 2514, 4353, 4886) overlap min-width:1024px: at exactly 1024px matchMedia returns true for both, so the three-card Dashboard row is squeezed and the label overlaps its pill ("PENDING ARTIST REPLY" / "Action Needed"). (c) Also in use: 560, 640, 767, 768, 840, 1024.
Expected
Mobile <768, tablet 768–1023, desktop ≥1024, single source of truth.
Recommendation
Align every query to the three approved ranges (use 1023 as the upper bound of tablet rules, remove the 840 shell rule). Do not change the approved breakpoints themselves. See I-5, I-6, I-16.

D. Accessibility audit (target WCAG 2.2 AA)

Verified defects

  • 1.4.3 / 1.4.11: dark-theme contrast (F-01), 1.0–2.65:1 on titles, labels, buttons, tabs.
  • 2.1.1: profile trigger (F-05); table rows (F-08).
  • 4.1.2: tablet nav links nameless (F-07); tabs/menus without state (F-14); Team modal without role (F-06).
  • 2.4.2: constant page title (F-11). 1.3.1 / 2.4.6: heading levels (F-11).
  • 1.3.1 / 3.3.2: placeholder-only labels (F-13).
  • 2.5.8: 22 targets under 24px at 1440 across routes (F-12); 2.5.5 (AAA) / spec 44px widely missed.
  • 2.4.3: no initial focus; no trap (F-06).

Verified working

  • Escape closes Profile, Assign, Team, kebab menu, half-pane.
  • Focus returns to the opener for Team and Assign.
  • lang="en", landmarks (nav, header, main, aside), viewport meta.
  • Sheet has role="dialog", aria-modal, label.
  • Status/alert regions for toast and form messages.
  • prefers-reduced-motion rule present.
  • Row actions and Notifications buttons have names; header/row checkboxes named.
  • Light-theme text contrast passes by computed estimate.

Needs assistive tech or manual testing

  • Real Tab/Shift+Tab order, trap, focus ring visibility (F-25).
  • Screen-reader announcements (route changes, bulk bar, toast).
  • Non-text contrast of borders and focus rings on both themes.
  • Error identification in forms (save flows not run).
  • Zoom to 200% / reflow at 320 CSS px; text-spacing override.
  • Pointer-gesture alternatives; drag/long-press selection on touch.
  • An automated axe pass: the repo's run-axe-audit.py needs Selenium/Edge and was not run (no installs).

Compliance statement: none made. Visual and computed-style inspection cannot establish WCAG conformance. Based on the verified defects, the application does not currently meet WCAG 2.2 AA in dark theme or for keyboard operation.

H. Testing limitations

  • Environment: mock backend with seeded sample data only. Behaviour against Google Sheets, Drive, Calendar, Docs and the AI service was not tested, nor were production data or authentication.
  • Viewports not tested: 390 and 1280 (not swept). 767 and 1023 boundary widths unreliable in the pane. No real phone, tablet or touch device; iOS Safari and Firefox not tested.
  • Themes: contrast sweep ran on 12 routes in both themes. Visual screenshots were taken for a subset. Dark Drafts and Archive screenshots, and dark mobile for most routes, were not reviewed visually. Charts: Analytics progress bars only (no real charts exist).
  • Routes with partial coverage: Drafts (1 draft only), Archive (empty), Add (no upload), Artist Call (only the Harsha/5 sample), Doc Review (external link not followed). Loading and error states could not be reproduced safely.
  • Interactions not exercised: every save, send, approve, archive, delete, upload, paste, sign-out, outcome, payment, copy, folder and Google Doc action. Category/Artist filter results. Cycle select. Confirmation dialogs.
  • Accessibility: focus trapping, tab order and focus ring appearance were inspected through DOM/CSS and synthetic events, not by real keyboard traversal. No screen-reader, no automated axe run, no 200% zoom or text-spacing test.
  • Screenshots were captured while some transitions were in flight; those used show the settled state or are noted. Contrast numbers use computed colours and ignore gradients, images and opacity inheritance beyond the parent chain.
  • Side effect: the browser-pane theme was switched Light, Dark, Light (stored under oc_theme in the pane's local storage). It was returned to Light; the original stored value was not captured. No application file was written.
  • The harness server on port 8787 was already running and was left untouched. The server on port 8080 (an unrelated Python app) was not used.
